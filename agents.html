Part 4 - Agents: AI That Does Things

Everything so far describes an AI that talks. The frontier of AI right now is systems that act - booking things, researching across many sources, writing and running code. These are called agents.

From answering to acting

A plain chatbot has exactly one ability: read text in, write text out. It can't check today's weather, open a file, or send an email. Every fact it offers comes from frozen training data.

The breakthrough idea is tool use. Developers give the model a menu of tools it's allowed to request - "search the web", "read this file", "run this calculation", "send this message" - and the model, instead of only writing prose, can write a special structured request like: use tool: search, query: "weather Sydney today". The surrounding software actually runs the search, feeds the result back into the model's context window, and the model continues from there.

A plain LLM is like a brilliant advisor locked in a room with no phone and no internet - they can only tell you what they already know. An agent is the same advisor given a phone, a laptop, and permission to make calls on your behalf. Same brain; vastly more useful - and requiring rather more trust.

The agent loop

An agent works in a repeating cycle: think → act → observe → repeat, until the job is done. The model looks at the goal and everything it has learnt so far, decides on a next step, uses a tool, sees the result, and reconsiders. Step through a realistic example:

What makes agents different from chatbots

ChatbotAgent
TurnsOne reply per messageMany steps per task, often without you watching
AbilitiesText in, text outCan use tools: search, files, code, apps, email
KnowledgeFrozen at training timeCan fetch live, current information
Failure modeWrong answerWrong action - which is why permissions matter

Ways of connecting AI to the world

A few terms you'll hear around agents, decoded:

Tool use / function calling. The core mechanism above: the model requests an action, external software executes it, the result comes back as text.

RAG (retrieval-augmented generation). Before the model answers, relevant documents (your company wiki, a manual, your notes) are automatically found and pasted into its context window. It grounds answers in real sources instead of memory alone - hugely reduces hallucination for factual work.

MCP (Model Context Protocol). A standard "plug socket" that lets any AI app connect to any tool or data source that speaks the same standard - rather than every company inventing its own connectors.

Multi-agent systems. Several agents working together - one plans, one researches, one writes, one checks. Early days, but it's where a lot of current development is heading.

The trust question

Agents inherit every limitation from the earlier chapters - hallucination, sensitivity to phrasing - but now with the ability to act. A chatbot that hallucinates gives you a wrong sentence; an agent that hallucinates might email the wrong person. That's why well-designed agent products do things like ask for confirmation before consequential actions (sending, buying, deleting), run risky operations in a sandbox - a safe, isolated environment - and keep a visible log of every step so you can audit what happened.

Practical advice Start agents on low-stakes tasks (research, drafting, organising files) and review their work, the same way you'd onboard a new assistant. Expand their responsibilities as they earn trust.
Key takeaway An agent is an LLM in a loop with tools: it thinks, acts, observes the result, and repeats until the task is done. Same prediction engine as a chatbot - plus hands.

Where to go from here

You now have the full picture: text becomes tokens, models learn by predicting them, you steer them with good prompts, and agents put the whole thing in a loop with tools. The best next step is practice - take a real task from your week and work through it with an AI assistant, applying what you've learnt. The glossary is there whenever a term trips you up.
